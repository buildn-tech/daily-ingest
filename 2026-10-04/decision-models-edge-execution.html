Decision Models + Edge Execution

Two Cloudflare announcements make a useful architectural pair: Clef supplies fast, typed decisions for agent hot paths; Dynamic Workers supply lightweight isolation for generated code. Together they suggest a pattern for high-volume automation: decide narrowly, execute ephemerally, and keep permissions explicit.

Clef decision models

fresh signalopen source models
  • What: Cloudflare released Clef and Clef-flash as Apache-2.0, Jev-API-compatible decision models with bounded outputs and probabilities.
  • Why now: The model is aimed at routing, escalation, tool choice, and human deferral—not chat novelty.

Buildn/client use: Use a small decision model for intake classification, report QA routing, or approval triage before invoking a larger agent.

Caveat: Cloudflare reports benchmark wins; validate on Buildn’s own false-positive and abstention cases.

  • Build a 50-example routing eval with an explicit defer-to-human class.
  • Keep evidence linked to output.

Dynamic Worker Loader

fresh signaledge sandbox
  • What: AI-generated JavaScript can run in a fresh V8 isolate with explicit RPC bindings and blocked outbound access.

Caveat: Open beta, JavaScript-first, and still requires careful capability design.

Code Mode economics

design patternagent workflow
  • What: Code Mode compresses many tool calls into generated code; Cloudflare cites an 81% token reduction in one MCP conversion.
  • Why now: Tool-call overhead becomes material when agents operate at consumer or batch scale.

Buildn/client use: Expose a narrow typed API to generated code instead of a large tool catalog.

Caveat: Token savings do not remove the need to inspect generated code and results.

  • Compare sequential tools versus one typed code-mode workflow.
