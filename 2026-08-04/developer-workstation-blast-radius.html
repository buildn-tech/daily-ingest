Wiz Sensor for Developer Workstations

product2026-08-03

What — Private-preview Windows/macOS sensor for inventorying packages, secrets, IDE extensions, AI tools, agents, MCP servers, skills, and models; it connects findings to cloud and code context.

Why now — It frames AI coding governance as endpoint-to-cloud exposure mapping rather than a standalone assistant policy.

Use — Buildn: make a lightweight inventory of developer agents, MCP servers, package managers, and privileged tokens. Client work: use the same inventory as a discovery deliverable before deploying coding agents.

Caveat — This is a vendor preview and the risk claims are vendor-reported; validate coverage, privacy, and MDM fit before depending on it.

Next move — Create a 30-minute inventory worksheet for one developer workstation and one CI runner.

Vercel WAF for Blob — general availability

release2026-08-03

What — Edge WAF rules can deny, challenge, or rate-limit requests to Blob stores without changing blob URLs or application code.

Why now — Agent-generated media, uploads, and paid files are often treated as passive storage; edge rejection reduces both exposure and transfer cost before a request reaches the store.

Use — Buildn: protect public artifact and upload stores with path/IP/rate rules. Client work: add storage access rules to every AI media delivery checklist.

Caveat — WAF rules do not replace object authorization or classification; test intended public paths before enforcing challenges.

Next move — Audit each Blob store: public purpose, allowed paths, rate limit, and owner.

Share Vercel Container Registry repositories across teams

release2026-08-03

What — Repositories can be shared read-only with up to 100 teams; recipients can pull images but cannot push, delete, or re-share.

Why now — Reusable sandbox images no longer require copying artifacts or granting image-maintenance authority to every consumer team.

Use — Buildn: publish a hardened base image to a delivery team with read-only access. Client work: separate image builders from agent-runtime consumers.

Caveat — Repository-wide access covers every image in that repository; split sensitive and general-purpose images first.

Next move — Create a dedicated hardened-agent-base repository and grant pull-only access.
