Sandboxed Browser Agents

Browser control has moved closer to an agent runtime with explicit isolation, domain boundaries, and approval hooks. Treat it as an execution surface: restrict destinations, preserve proof of what the agent saw, and keep credentials outside the model toolset.

Give your eve agent a browser

release2026-08-04

What — An Eve extension mounts agent-browser tools for navigation, snapshots, clicks, forms, screenshots, and network inspection inside the agent sandbox.

Why now — This is the material update to agent-browser previously tracked in July: it now has a first-party sandboxed agent integration with allowlists and model-tool controls.

Use — Buildn: prototype a research or QA agent with an explicit client-domain allowlist. Client work: offer browser-assisted support or regression checks without giving the runtime workstation access.

Caveat — Browser actions can still create external effects. Keep payment, account changes, and irreversible submissions behind approvals.

Next move — Build a two-domain sandbox proof of concept; deny every other destination.

Eve + agent-browser integration guide

docs2026-08-04

What — The integration documentation defines extension mounting and the browser tool contract used by Eve agents.

Why now — The useful design detail is not raw clicking; it is namespaced, inspect-then-act tools that allow policy to sit around the browser capability.

Use — Buildn: standardize a browser extension wrapper with output caps and evidence screenshots. Client work: expose a narrow, auditable browser task instead of a general browsing agent.

Caveat — Documentation and product behavior can drift; test the installed extension version in the target sandbox image.

Next move — Add a small acceptance suite: blocked domain, approved click, and screenshot evidence.

vercel-labs/agent-browser

repo2026-08-02

What — Apache-2.0 browser automation CLI with accessibility snapshots, stable element references, MCP tools, and a native Rust daemon.

Why now — Stable snapshot references support evidence-led browser interaction instead of brittle coordinate automation; the recent doctor fix also improves workstation diagnostics.

Use — Buildn: use snapshots as review artifacts in automated web research. Client work: evaluate it where Playwright-sized stacks are unwanted.

Caveat — A local browser daemon is a long-lived process; retain the default idle cleanup and avoid persistent authenticated state.

Next move — Run the CLI in a disposable sandbox, then verify idle cleanup and no credential-state commands.
