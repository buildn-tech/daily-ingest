Daily Ingest Dossier — Agent Memory That Can Be Governed

2026-11-21 · lane selected for a neglected but high-leverage operational gap

The newest useful memory work shifts the question from “can the agent remember?” to “who schedules recall, who can delete it, and what happens when memory is poisoned?” The practical design is a separate, inspectable memory plane with task-conditioned evaluation and explicit user sovereignty.

HEAMS: stop collapsing memory quality into one score

high leverageresearch + open source
  • Source: HEAMS: Holistic Evaluation of Agent Memory Systems
  • Code: github.com/milatechtransfer/heams

What it is: An open, configuration-driven framework evaluating performance, efficiency, privacy, user sovereignty, and security side by side.

Why it matters: A memory layer can improve task success while failing deletion, contextual privacy, or poisoning resistance.

  • Adopt five-axis acceptance tests
  • Measure deletion and recall
  • Keep governance trade-offs visible

Action: Run HEAMS-style checks against any persistent Buildn memory prototype before optimizing retrieval quality.

MemSidecar: move retrieval scheduling off the main agent

architecture patternlong-horizon work
  • Source: Who Schedules Agent Memory?

What it is: A sidecar with event-triggered Hooks and asynchronous Foresight retrieval, separated from the task agent’s planning loop.

Why it matters: The main agent often does not know it needs memory until the decision point has passed. A sidecar can prefetch, trigger, deduplicate, and pack context without blocking execution.

  • Prefetch likely constraints
  • Keep task loop simpler
  • Separate global/workspace memory
  • Log why memory arrived
Caveat: asynchronous recall can add irrelevant context; require relevance thresholds and a visible provenance trail.

MemUse: evaluate memory at the moment it is delivered

measurement gapagent evaluation
  • Source: Delivered, Not Used: Evaluating Agent Memory at Its Point of Use

What it is: A framework for evaluating individual memory deliveries in recorded agent trajectories, rather than assuming that retrieved context was useful.

Why it matters: “Memory retrieved” is not the same as “memory used correctly.” Retrieval-only metrics inflate value and hide late, ignored, or misleading memories.

  • Score delivery timing
  • Track use versus discard
  • Compare memory-on/off baselines

Action: Add a memory-use event to agent traces: delivered, cited, applied, contradicted, or ignored.

Task-conditioned utility: recall is not inherently helpful

research signalpersonal leverage
  • Source: What Is This Memory Useful For?

What it is: A study framing long-term memory utility as conditional on the task, including counterfactual evaluation.

Why it matters: A durable memory should earn its place by improving a specific decision, not by being globally retrievable.

  • Test task-specific utility
  • Prefer reversible retention
  • Expose stale assumptions
