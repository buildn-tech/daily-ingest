1. OKF v0.2 adds trust signals

What it is
Google’s Open Knowledge Format v0.2 adds optional provenance, generated/verified, stale_after, status, and attestation vocabulary to Markdown/YAML knowledge bundles.
Buildn / client use
Create a small Buildn project-context bundle for one client: canonical metrics, runbooks, ownership, source links, and a re-verification date.

Why useful now: This deliberately rotates toward an under-covered data-contract lane: agents need inspectable provenance and authorization boundaries before they can safely act on operational knowledge.

Caveat: The format records signals rather than enforcing policy; consumers still need rules for what they may trust or execute.

Follow-up action: Prototype three files: a metric, a runbook, and a client constraint with stale_after dates.

3. ORDS 26.2 MCP support for agentic database access

What it is
Oracle REST Data Services 26.2 can act as an MCP server: authorized agents can list databases, inspect schema metadata, and run SQL/PLSQL under granted privileges.
Buildn / client use
The tool split is a useful pattern for client data work: discover, inspect, then act—each bounded by an existing identity and role.

Why useful now: This deliberately rotates toward an under-covered data-contract lane: agents need inspectable provenance and authorization boundaries before they can safely act on operational knowledge.

Caveat: SQL execution is high authority; OAuth compliance does not make broad database credentials safe for agents.

Follow-up action: Write a three-tool policy for any database agent: read metadata, parameterized read queries, and separately approved writes.
