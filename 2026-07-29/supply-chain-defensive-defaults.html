release2026-07-28

GitHub Actions holds potentially malicious workflows for approval

SOURCE · https://github.blog/changelog/2026-07-28-github-actions-holds-potentially-malicious-workflows-for-approval/

What changedGitHub now pauses certain suspicious public-repository workflow runs for authenticated collaborator approval before execution.
Why it mattersStops a compromised credential from immediately turning a workflow change into CI-secret theft.
Buildn / client useEnable least-privilege Actions tokens; review held runs through an incident playbook.

Caveat. Public github.com only; it is a safety net, not a substitute for branch protection.

Follow-up: Add “held workflow” ownership to the release-security checklist.

release2026-07-28

npm publish-time malware scanning and dual-use metadata

SOURCE · https://github.blog/changelog/2026-07-28-npm-publish-time-malware-scanning-and-dual-use-metadata/

What changednpm scans a new package before install availability; dual-use packages require declared metadata, a DISCLOSURE file, and 2FA-enforced publishing.
Why it mattersRelease pipelines that immediately install a just-published package now have a real availability dependency.
Buildn / client useMake package smoke tests retry-aware; use trusted publishing for client packages.

Caveat. Scanning can delay availability and declaration does not guarantee publication.

Follow-up: Audit any publish → install CI chain for a 15-minute readiness window.

release2026-07-28

Dependabot alerts on malicious packages across more ecosystems

SOURCE · https://github.blog/changelog/2026-07-28-dependabot-alerts-on-malicious-packages-across-more-ecosystems/

What changedGitHub now ingests OpenSSF malicious-packages advisories into the Advisory Database for Dependabot malware alerts.
Why it mattersDetection coverage broadens beyond one registry and converts community malware intelligence into repository alerts.
Buildn / client useConfirm Dependabot malware alerts at organization level; route alerts into the same triage queue as vulnerabilities.

Caveat. Only known, reported malware is covered; lockfiles and dependency review still matter.

Follow-up: Verify malware alerts are enabled in Buildn and active client repositories.
