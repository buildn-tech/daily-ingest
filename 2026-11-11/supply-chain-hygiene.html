Signal map

Thesis: security coverage must be an explicit invariant.

Dependabot alerts will pause on inactive repositories

fresh · primary source

Effective 8 Dec 2026 · all GitHub.com plans · archived, not deleted

What: most repositories with no activity for a year will have Dependabot alerts turned off. A push or re-enable action restores them; enforced security configurations and enterprise policies are exempt.

Why it matters: long-lived client repos, templates, archives, and infrastructure definitions may silently lose vulnerability visibility.

Use: inventory inactive repos, classify which are still production-relevant, and enforce alerts for those that matter.

Caveat: the policy is about alerting, not whether the dependency is safe. Archived findings can still hide operational debt.

Next: add “security coverage enforced?” to every repository handoff checklist.

Agent-authored code raises the baseline

workflow implication

When agents create branches, dependencies, and package changes, a quiet repository can still be a high-risk artifact. The repository must carry its own trust boundary: lockfiles, review ownership, secret scanning, dependency alert policy, and a restore path.

  • Require security policy in repo configuration.
  • Keep inactive but critical repos under enterprise enforcement.
  • Record last scan and last human review in delivery metadata.
Treat “no recent commits” as a signal to review coverage, not permission to stop watching.
