1. Workflow steps now support extended function durations

What it is
Vercel Pro and Enterprise workflow steps can run up to 30 minutes, up from 800 seconds, after enabling an environment flag; Hobby remains capped at five minutes.
Buildn / client use
Use it for one bounded, resumable client task such as a site audit or media transformation, with an explicit timeout and output contract.

Why useful now: This is a deliberately narrow operational lane: recent coverage examined agent authority, while these releases expose the runtime, time, and stored-output boundaries an operator must now govern.

Caveat: The feature is beta, plan-gated, and requires Fluid compute plus a supported runtime.

Follow-up action: Classify current jobs by five-minute, 13-minute, and 30-minute needs before enabling the flag.

2. Connect to and manage Sandboxes from the dashboard

What it is
The dashboard can now open a terminal into a running Sandbox, browse files, transfer files, inspect ports, snapshot, stop, and resume persistent sandboxes.
Buildn / client use
Add an operator inspection step for agent runs that produce deployable files or need incident triage.

Why useful now: This is a deliberately narrow operational lane: recent coverage examined agent authority, while these releases expose the runtime, time, and stored-output boundaries an operator must now govern.

Caveat: Browser terminal access widens the administrative surface; access reviews and secret hygiene still apply.

Follow-up action: Document which roles may connect, export files, snapshot, or expose ports for each sandbox class.

release2026-07-24

3. Vercel WAF for Blob is now in beta

What it is
Vercel can apply deny, challenge, rate-limit, redirect, and log rules at the edge for Blob stores without changing blob URLs or application code.
Buildn / client use
Protect client downloads, generated reports, and expensive media endpoints before transfer occurs.

Why useful now: This is a deliberately narrow operational lane: recent coverage examined agent authority, while these releases expose the runtime, time, and stored-output boundaries an operator must now govern.

Caveat: One shared rule set covers every protected store; challenge rules block matching server-side blob requests.

Follow-up action: Inventory public Blob paths, then pilot a rate limit and logging rule on one non-critical store.
