The fresh signal is not “robots are solved”; it is that GPU-native simulation is becoming easier to batch, inspect, and connect to control policies. For Buildn, the practical opportunity is a small sim-to-real evaluation harness—not a moonshot hardware program.

Newton v1.5.0

Open the release notes →

What it is: an open-source GPU-accelerated physics engine targeting robotics and simulation research, with v1.5.0 expanding scalable batched simulation and control workflows.

Why now: batchability makes evaluation cheaper and exposes policy brittleness sooner.

Buildn/client use: prototype a reproducible “policy smoke test” for embodied workflows or industrial automation vendors.

Caveat: physics fidelity and available robot assets still determine whether a benchmark transfers.

Action: run one documented manipulation task across 32 seeds and record failure clusters.

Genesis 1.3.x

alternativeresearch

Read the release notes →

What it is: a differentiable simulation stack whose recent releases improve rigid-body invariants, numerical robustness, and differentiable simulation maturity.

Why useful: differentiability changes the experiment design: optimization and sensitivity analysis can sit closer to the simulator.

Action: use it as a control condition, not a default; compare setup friction and task validity against Newton.

Do not equate “differentiable” with “realistic”; validate against observed trajectories.
