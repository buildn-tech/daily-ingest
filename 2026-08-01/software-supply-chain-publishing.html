Restricting npm 2FA-bypass granular access tokens

UPDATED 2026-07-31 · PRIMARY SOURCE

What: Bypass-2FA granular tokens can no longer manage tokens, access, maintainers, trusted publishing, organizations, teams, or grants.

Why now: A leaked automation credential loses a set of account-takeover and package-control paths.

Buildn/client use: Audit Buildn/client publish secrets and separate administrative actions from release automation.

Caveat: The restriction applies to npm GATs—not GitHub PATs, App tokens, or GITHUB_TOKEN.

Next move: List all bypass-2FA npm tokens and label each as read, stage, or publish automation.

npm trusted publishers documentation

UPDATED 2026-07-31 · PRIMARY SOURCE

What: npm documents OpenID Connect trusted publishing for supported CI/CD providers.

Why now: It is the intended replacement path before bypass-2FA tokens lose direct publishing, targeted for January 2027.

Buildn/client use: Migrate a low-risk package from stored registry token to CI workload identity.

Caveat: Provider and repository configuration must be exact; test provenance and rollback paths before switching production release.

Next move: Open a test-package issue: convert one release workflow to trusted publishing and verify a dry release.
