2026-08-01 · ADAPTIVE DISCOVERY

Agent spend is now governable at the same scopes where delivery is owned. Treat the cap as a safety boundary, then use route-level traces to decide whether the boundary is correctly sized.

Signal map

Yesterday covered routing economics; today’s material update is the control plane around it: hard team/project/key caps and request-level routing evidence turn an experiment into an operable service.

Selected dossiers

release

AI Gateway now supports team and project spend budgets

UPDATED 2026-07-31 · PRIMARY SOURCE

What: Hard dollar budgets now apply to teams, projects, and API keys; a request must pass every applicable budget.

Why now: Moves cost control from after-the-fact reporting to enforced scope-level limits.

Buildn/client use: Give each client pilot a project ceiling and every agent key a smaller blast-radius cap.

Caveat: A reached limit rejects requests; alerts are off by default, and BYOK spend is excluded by default.

Next move: Create one low ceiling for a non-production agent, enable alerts, and rehearse the exhausted-budget path.

release

AI Gateway logs now have a dedicated page

UPDATED 2026-07-30 · PRIMARY SOURCE

What: A request log exposes cost, token classes, latency, routing, fallback attempts, region, and ZDR status; filtered views export as CSV or JSON.

Why now: A failed or expensive agent run can be explained by evidence rather than an aggregate bill.

Buildn/client use: Attach a filtered incident or client-run view to a delivery review; compare fallbacks before changing model policy.

Caveat: This visibility is gateway-scoped; it does not replace application-level outcome telemetry.

Next move: Define saved filters for production failures, slow requests, and spend spikes.

release

DeepSeek V4 Flash updated weights on AI Gateway

UPDATED 2026-07-31 · PRIMARY SOURCE

What: The existing model ID now routes to updated weights; Vercel reports Terminal-Bench 82.7, up 25.8 points from the April preview.

Why now: A silent model-weight shift is exactly the kind of material change that needs a bounded, observable re-evaluation.

Buildn/client use: Run a fixed internal coding-task set before moving this route into a client or Buildn workflow.

Caveat: The stated benchmark is provider reporting; updated weights are initially served only by DeepSeek.

Next move: Pin a before/after evaluation set and log reliability, cost, and review burden.
