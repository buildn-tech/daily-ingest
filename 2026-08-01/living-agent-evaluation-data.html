paper

Change2Task: From Repository Changes to Executable Coding Agent Tasks and Environments

UPDATED 2026-07-30 · PRIMARY SOURCE

What: A research system reconstructs verified coding-agent tasks from merged PRs against healthy modern revisions using patch reversal, code mapping, and agent reconstruction.

Why now: It tackles the expensive failure mode where historically real tasks no longer execute on obsolete repository states.

Buildn/client use: Prototype a Buildn evaluation corpus from merged client-safe PRs, with tests as acceptance evidence.

Caveat: Reported results are from a research pipeline, not a turnkey production tool; task leakage and access controls remain local responsibilities.

Next move: Select ten merged, non-sensitive PRs and classify whether each has a durable executable acceptance test.

paper resource

Change2Task experimental HTML and resources

UPDATED 2026-07-30 · PRIMARY SOURCE

What: The paper reports 79.6% verified construction across 1,130 eligible changes, 29.2% more verified tasks than its PR-based baseline, and up to 98.0% outcome agreement.

Why now: The numbers make a credible case for testing reconstruction before funding a manually curated benchmark program.

Buildn/client use: Use the lifecycle—healthy base → task state → restored state—as an acceptance contract for internal agent eval cases.

Caveat: Outcome agreement does not prove coverage of your stack, test suite, or engineering conventions.

Next move: Adopt the lifecycle check as a gate for every internally generated eval task.
