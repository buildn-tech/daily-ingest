Realtime interaction is now a product surface with explicit latency and spend choices. Treat voice and fast routing as measured interface experiments, not a blanket model upgrade.

Signal map

Two July 29 Vercel releases make low-latency agent interaction easier to route and instrument: a speech-to-speech model via a gateway and provider-neutral fast mode. This opens a client-experience lane that has been under-covered relative to back-office agents.

releasedirect source

Speech-to-speech, gateway-controlled

What: Grok Voice Think Fast 2.0 accepts audio and returns audio; Vercel recommends minting short-lived server tokens for browser sessions.

Why now: It is a credible prototype path for an interactive intake instead of a chain of separate STT, model, and TTS services.

Use: Buildn OS: spoken status intake. Client: guided discovery. Agents: voice-triggered research triage. Personal: hands-free capture.

Caveat: Voice requires consent, retention rules, fallback UX, and careful evaluation on noisy calls.

Next: Build a five-minute internal intake with explicit transcript review before any action.

releasedirect source

Fast mode is a routing policy

What: AI Gateway fast mode requests a lower-latency tier when available and falls back to standard; it costs more per token.

Why now: Speed becomes a workflow-level dial instead of a provider-specific integration decision.

Use: Buildn OS: urgent operator requests. Client: first-response experience. Agents: short interactive turns. Personal: reserve for time-sensitive work.

Caveat: It is beta and not universal; pricing and actual latency must be measured per model and route.

Next: Instrument p50/p95 latency, completion quality, and cost for fast versus standard on 30 tasks.

releasedirect source

One modality surface, several fallbacks

What: The realtime API covers realtime voice, speech generation, and transcription.

Why now: A prototype can preserve accessibility and reliability with text and transcript paths, not just a single voice interaction.

Use: Buildn OS: transcript-first audit trail. Client: text fallback. Agents: classify voice requests. Personal: searchable notes.

Caveat: Do not let audio novelty obscure authorization, disclosure, and escalation requirements.

Next: Define a voice-to-text fallback and human escalation before testing external users.
