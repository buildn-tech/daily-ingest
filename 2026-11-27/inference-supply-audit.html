Daily Ingest Dossier — Inference Supply Chain Audit

Friday, 27 November 2026. Yesterday covered agent store-shelf supply chain (malicious PyPI packages); today's lane is the inference-side half of the same problem, and it is bigger: one researcher traced hundreds of billions of tokens per week from "US ZDR providers" through nested shells to ByteDance Ark, right after the MiniMax URL-reading incident proved the forwarding is real and has privacy consequences. If you route model traffic, your data-residency story is only as good as your provider's family tree.

Novita, StreamLake, Ant Digital are Ark wrappers

audit nowinvestigation
  • kendell.dev · Nov 25, 2026
  • DeepSeek tokens on routes traced to ByteDance Ark: ~1.1T/week (Novita) + ~430B (StreamLake)
  • Fingerprints: shared error strings, tool-call id formats, req-id passthrough across 41 hosts
  • OpenRouter ZDR flags flipped days before public disclosure

What it is. A forensic trace, built from observable fingerprints rather than speculation: token-volume graphs, error-message wording, tool-call id formats, and request-id passthrough that tie supposedly independent providers back to one upstream host. The draft IPO of the parent even promises "no pass-through gateway" — the opposite of what the evidence shows.

Why it matters now. This lands days after MiniMax's confirmed URL-reading incident, in which requests forwarded by exactly these three providers were opened by MiniMax's security system, including ZDR-flagged ones. ZDR is a per-provider claim about a path you cannot see; the claim breaks when the path is longer than advertised.

Buildn / client use. Egypt lead-gen and any client data going through coding or voice agents: inventory every provider in every API key, ask the sub-processor question with this article in hand, and prefer self-hosted or first-party endpoints for anything sensitive. Cheap differentiation for Env Vault marketing: "device-key encryption with a provable inference path".

  • Evidence, not rumor
  • ZDR claims now falsifiable
  • Direct client pitch material
The author publishes this as an ongoing watch, not a one-off exposé; volumes are lower bounds on selected models. Treat any provider's ZDR claim as unverified until they name their model subprocessors.

The MiniMax forwarding incident, named and admitted

privacyincident

What it is. The cleanest demonstration to date that resold inference is a data channel: a security system "on by default" fetched URLs embedded in prompts that arrived via forwarders, including zero-data-retention ones.

Buildn / client use. This is the compliance story to tell prospects: every hop in an inference chain is a potential processor under GDPR-adjacent rules. A one-page "who processes your prompts" audit is now a sellable service.

Google Workspace MCP: agents must use Google's servers from Feb 2027

complianceplatform
  • workspace.google.com/terms/ai-tools · announced Nov 24
  • From Feb 1, 2027: AI-agent-driven tools must call Workspace via Google MCP servers
  • Gmail MCP cannot send/reply/forward — those stay partner-gated
  • 30-day cap on "Google Technical Information" (embeddings, memory indexes, org graphs)

What it is. A platform boundary drawn in terms of service: the agent-shaped path must go through Google's own MCP layer, with agent-disguise explicitly banned, and long-term memory built from Workspace data capped at 30 days.

Why it matters now. Everyone building Gmail/Calendar agents has ~9 weeks. The 30-day memory cap kills the "index my whole inbox once" pattern; agents must rebuild or slice monthly. It is also a preview of how other platforms will gate agent access — capability lives at the platform's MCP layer, not yours.

Buildn / client use. The Hermes/Buildn Gmail integration should check which side of this line it sits on now, not in January. For client work: an "agent platform compliance readiness" checklist (which APIs, which tier, which memory architecture) is a fixed-fee engagement waiting to happen.

  • Hard date: Feb 1
  • Memory capped at 30d
  • Send stays partner-gated
