Daily Ingest Dossier — Sandboxed Execution Comes to Node

Friday, 27 November 2026. The week's agent-security coverage (side channels Nov 26, malicious packages Nov 26, runtime shields Nov 24) converged on one missing primitive: a way to run untrusted agent-generated code safely inside your own process. Today that primitive showed up on HN as NormalScript — a strict JavaScript subset VM for Node ≥ 24 / Bun ≥ 1.4 that pauses runs to bytes and resumes them anywhere. Alongside: an AI-vs-browser cross-testing rig and a Rust VoIP stack with AI voice agents behind one API.

NormalScript: a JS subset VM that embeds in your app

try todayshow hn
  • psychoscript.com · github.com/anomalyco/psychoscript · HN 104 pts
  • Node ≥ 24 or Bun ≥ 1.4 · no WASM, no native addons, no workers
  • 19,408 test262 files passing · 2,845 known gaps · 0 failing
  • Run → pause to bytes → resume elsewhere · timeoutMs + AbortSignal

What it is. A small bytecode VM for a strict-mode JavaScript subset (async/await, classes, generators; no eval, Proxy, typed arrays beyond Uint8Array, no module loader, no ambient I/O). Capabilities enter as host functions, which is what makes it safe: the guest can only touch what you hand it. The pause-to-bytes primitive means a long agent workflow can survive restarts and even move hosts.

Why it matters now. The exact gap from this week: you don't want agent-written code holding a raw `fs`, but you also don't want to stand up a container per invocation. This runs in-process, sandboxed by omission, with resumability built in — the shape of an Env Vault local-trusted execution layer or a Buildn OS "untrusted step" runner.

Buildn / client use. Prototype path: wrap one Buildn workflow step as a NormalScript guest whose only host functions are scoped MCP calls (read task, write artifact). If it holds up, this becomes the default for agent-authored automation inside client apps — safer than eval, cheaper than sandboxes.

  • In-process, zero infra
  • Resumable to bytes
  • test262-honest subset
No timers or event loop — scripts run to completion or abort, so long-running coordination needs the host to drive. New project; API stability is unproven. The satirical site is a brand choice, not a red flag — the README and test matrix are the real review surface.

Side by Side: three browser engines, one URL, one tab

qa toolshow hn
  • michidk.github.io/sidebyside · HN 137 pts
  • Three Linux VMs in a browser tab, each running a different browser
  • Zero-install cross-engine visual regression checking

What it is. A demo rig that runs the same URL in three different browsers via streaming Linux VMs, side by side. Immediately useful for the class of bug where WebKit and Chromium disagree — which is exactly where agent-generated front-end code fails silently.

Buildn / client use. Add to the QA loop for any client web build with mobile/WebKit share: paste the staging URL, eyeball three engines at once. Cheaper than a BrowserStack seat for spot checks.

  • Zero-install engine diff
  • Catches WebKit drift

rvoip: Rust SIP/WebRTC stack with AI voice agents behind one API

  • SIP, WebRTC, SRTP, AI voice agents in one API · RFC 7502-benchmarked

What it is. An open-source, self-hostable alternative to the hosted voice stack (Telnyx et al.): the telephony layer as a library, with the AI-agent interface as a first-class citizen rather than a bolt-on.

Buildn / client use. The self-hosted escape hatch from Nov 26's hosted-voice pricing: if a client's call volume grows past hosted economics, rvoip + a local model is the path. Track its maturity before recommending; v0.x means evaluation-only today.

  • Self-hosted voice path
  • Agents as first-class API
Pre-1.0; RFC-benchmarked is promising but not a deployment endorsement. Pilot on a non-critical line first.
