Songe: a training engine running on your idle compute

try todayopen sourceshow HN
  • github.com/sous-labs/songe · Python · active (commits Nov 25)
  • Records agent conversations → Quick Dreams (preferences) → Deep Dreams (trained adapter)
  • Adapter deploys only if it passes its own checks; MLX servers supported

What it is. A proxy that records how you actually use a local model, distills preferences and lessons, trains a small adapter ("Deep Dreams"), and ships it only if a behavior-drift gate says the model still acts the same where no lesson applies.

Why it matters now. The gate is the interesting part: it treats personalization as a measured deployment decision, not a blind fine-tune. That is the same evidence-gated pattern Buildn uses for agent changes — now applied to model weights on a laptop.

Buildn / client use. A concrete demo of "learning from usage with a review gate" for any client worried about personalization drift. Practical if you run local models on a Mac (MLX).

  • Personalization with a deployment gate
  • Idle compute, no training cluster
  • Drift measured as KL against base model
Early alpha (0.1.0a13); expect rough edges and Apple-silicon-first ergonomics.

Ternary Bonsai 2.5 27B: agentic coding in 5.9 GB

strong signalmodel releasefront page
  • prismml.com · Nov 24, 2026 · based on Qwen3.8 27B · 5.9 GB footprint
  • SWE-bench Verified 75.6 (vs 60.8 prior gen, 80.6 full precision)
  • AppWorld 90.5 · τ³-Bench 73.9 · 291 tok/s on one H100, 204 tok/s on RTX 4090

What it is. A near-lossless ternary compression of Qwen3.8 27B that closes most of the agentic gap to the full-precision model — fewer turns, fewer tokens, fewer repetitive loops than its predecessor — while fitting in 5.9 GB.

Why it matters now. Yesterday's Inkling 2 Mini lane showed tiny local models; Bonsai 2.5 shows 27B-class agentic coding squeezing into consumer GPUs. The "intelligence density" metric (benchmark points per GB) is the useful mental model.

Buildn / client use. A credible on-device coding/tool-use engine for privacy-sensitive client environments where code cannot leave the building. Pair with a local retrieval layer (see Rhebok below).

  • 75.6 SWE-bench in 5.9 GB
  • Fewer turns per task than Bonsai 2
  • Runs on a 4090
Still ~5 points behind the full-precision base on SWE-bench; benchmarks are vendor-reported.

Rhebok: local retrieval and memory for coding agents

try todayopen source
  • github.com/Stellenbosch-Technologies/rhebok · Rust · v0.2.2 (Nov 24)
  • One binary, no daemon · Ollama or any OpenAI-compatible embeddings
  • Indexes notes, docs, web pages, agent session transcripts; plugs into Claude Code, Codex, Cursor via hooks + MCP

What it is. Local-first RAG plus durable agent memory: vectors, BM25, and a property graph in one store (LadybugDB), with a local web dashboard.

Why it matters now. Most coding-agent memory tools assume cloud indexes. Rhebok keeps transcripts and lessons on your machine — the privacy-first answer to the "agent memory" lane covered repeatedly here.

Buildn / client use. Direct fit for Hermes/Buildn agent setups: cross-session memory for coding agents without sending code or history to a third party. Candidate to actually deploy this week.

  • Session transcripts become searchable memory
  • MCP server + hooks for major agents
  • No daemon, one binary

Carry: every AI conversation as Markdown you own

worth exploringproduct
  • carry.md · saves AI chats as local Markdown files

What it is. A small utility that exports AI conversations to a folder of Markdown you control.

Why it matters now. Same instinct as Rhebok from the consumer side: your agent history is an asset that should live in plain files, not a vendor database. Feeds naturally into local retrieval.

Buildn / client use. Cheap trust-builder for clients nervous about AI tool retention policies; also a personal-archiving habit worth adopting.
