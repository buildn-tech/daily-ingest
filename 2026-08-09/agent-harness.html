How building AI agents has changed in 2026

  • Source: Pulumi · practical architecture essay
  • Observed: current 2026 guidance; publication date not exposed in search result

What it is. A field report arguing that SDKs now ship the generic loop, tools, retrieval patterns, and progressive-disclosure skill systems that teams used to rebuild.

Why it matters. A new agent project should spend less time inventing a tool registry and more time specifying the bounded action surface, evidence model, and acceptance tests.

Buildn/client use. Treat Hermes skills as the default distribution layer; reserve MCP for external systems that truly need a server boundary; keep domain workflows in versioned, reviewable recipes.

Useful now. It gives a concrete build-vs-buy checkpoint for current automation work.

Caveat: The essay is vendor-adjacent and its “middle layer is gone” thesis needs workload-specific validation.
  • Audit duplicate tool wrappers.
  • Move stable recipes into skills.
  • Measure action quality, not tool count.

Follow-up: Pick one Buildn workflow and map generic harness features versus genuinely differentiating policy and domain logic.
