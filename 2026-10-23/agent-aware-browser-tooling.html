Daily Ingest Dossier — Agent-Aware Browser Tooling

23 October 2026 · adaptive lane

Executive readout. Browser agents are becoming infrastructure, not just UI automation. Chrome’s DevTools MCP makes permissions, JavaScript execution, file roots, plugin loading, and performance reproducibility explicit; PrefDiag-Bench and ASPIRE show why capability control must be paired with evidence selection, trigger timing, and influence-path testing.

Signal map: control the path, not the prompt

A prompt policy is not a boundary if the browser tool can still execute arbitrary code, read broad paths, or carry untrusted influence into privileged actions.

Chrome DevTools MCP — concrete least privilege

primary signalChrome 153/154
  • Agent Plugins 1.0
  • --no-javascript-evaluation
  • Configurable file-system roots
  • Reproducible CPU performance tiers

The October DevTools release makes agent capability boundaries legible: JavaScript can be disabled across navigations, source maps can be controlled, file roots can be configured, and heap/performance evidence can be queried.

  • Separate inspect from execute
  • Constrain filesystem scope
  • Make performance reproducible

Use now: Build a browser-agent test matrix with capabilities on/off, path scope, egress, and evidence produced.

Caveat: The release exposes controls; teams still need safe defaults and operational review.

Source: Chrome for Developers

PrefDiag-Bench — personalization fails before the click

research22 Oct

Personalized GUI tasks are not merely “complete the order.” The agent must select relevant history, infer how a preference changes the procedure, and recognize the exact state where it activates. The strongest reported system falls from 81.13% on basic tasks to 47.17% on process preferences with explicit profiles.

  • Score evidence selection
  • Test trigger timing
  • Separate outcome from process

Use now: Add tests such as “ask for confirmation immediately before submit” and record the evidence used.

Source: PrefDiag-Bench · code and dataset

ASPIRE — red-team influence paths

security lenspath coverage

ASPIRE searches consequences, injection methods, and environments while maintaining an Agent Security Behavior Graph. This reframes browser-agent safety from payload string filtering to the path an untrusted artifact takes into a privileged action.

  • Map retrieval to action
  • Track blocked vs untested
  • Retain strategy memory

Follow-up: Model every browser workflow as untrusted input → retrieval → observation → plan → tool → state change.

Source: ASPIRE paper
