Daily Ingest Dossier — Self-hosted Agent Execution

27 September 2026 · adaptive lane

The infrastructure question is shifting from “cloud or local?” to “which parts of the agent loop must remain under the customer’s control?” Coder Agents GA and Agent Relay make the split tangible: a familiar agent experience can coexist with self-hosted execution, private workspaces, model choice, and governance.

Signal map

What it is: Coder Agents runs the agent and execution on self-hosted infrastructure; Agent Relay keeps cloud-hosted agent UX while execution occurs in Coder workspaces.

Why it matters: Execution locality becomes an architectural choice instead of a vendor-wide switch.

  • Keep code local
  • Swap models
  • Centralize policy

Buildn/client use case

architecture benchmark
  • boundary: control plane / worker
  • asset: source, secrets, artifacts
  • decision: locality by risk

Use a two-axis architecture review: who controls the agent interface, and who controls execution. Low-risk work can use managed ergonomics; sensitive work should run in a customer-owned workspace with explicit egress.

Follow-up: Draw the boundary for one Buildn worker and list every data crossing it.

Self-hosting moves responsibility inward: patching, images, identity, observability, and incident response still need owners.
