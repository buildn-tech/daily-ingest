HappyDelivery is a practical multi-agent commerce pattern

buildableprototype
Google Developers Blog · 2026-10-27 · FastAPI + Pub/Sub + Redis + LangGraph

Google’s prototype separates ingress, session/cart state, and cognition. Webhooks authenticate and normalize events, return quickly, then specialized agents search inventory, mutate carts, calculate totals, and execute payment flows.

Buildn use: adapt the pattern to client intake or artifact triage: fast acknowledgment, durable case state, specialist agents, deterministic finalization. Caveat: idempotency and payment-like side effects need hard guarantees.

  • Keep channels replaceable
  • Queue before reasoning
  • Make side effects explicit

Generative UI needs a trusted catalog

design patternA2UI
Google Developers Blog · 2026-10-27 · catalog contract + deterministic compiler

A2UI’s model is compelling for conversational products: the client owns the component catalog and renderer, while the agent chooses among allowed structures. Express reduces generation cost without changing the transport.

Buildn use: let an agent compose a brief, compare options, or request approval without generating arbitrary application code. Caveat: catalog design determines what the agent can express.

  • Design the safe vocabulary
  • Keep rendering deterministic
  • Make approval visible

Human checkpoints belong in the workflow

operational patternverification
GitHub dynamic workflows · parallel stages + structured results + pause/resume

GitHub’s dynamic workflow model makes human review an explicit stage, not an informal interruption. Independent analyses can run in parallel, results can be structured, and a run can pause before a consequential step.

Buildn use: use the same pattern for client deliverables: gather evidence, draft, critique, then request approval before publish. Caveat: checkpoints are only useful if the reviewer sees evidence and can reject safely.

  • Review before side effect
  • Preserve structured evidence
  • Resume without rework
