Individual bypasses and required reviewers

oo
  • source · repository policy

What it is

https://github.blog/changelog/2026-08-11-github-enterprise-server-3-22-release-candidate/

Why it matters

GHES rulesets can target individual bypasses and require reviewers by path, including security, QA, design, or data teams.

Buildn / client use

Policy granularity is exactly what agent-generated changes need when code volume rises.

Why now

Require named review classes for agent changes touching auth, data, prompts, or deployment manifests.
Caveat: Overly granular rules can create approval fatigue and shadow bypasses.

Follow-up

Create a path-based ruleset for one agent-owned repository.
