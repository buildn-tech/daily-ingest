MCP allowlists in enterprise managed settings

security release2026-08-06test before adoption
  • DIRECT — https://github.blog/changelog/2026-08-06-mcp-allowlists-in-enterprise-managed-settings

What it is

Enterprise settings can allow or deny MCP servers by canonicalized remote URL, exact local command/arguments, or name; malformed or unverifiable configurations are blocked.

Why it matters

Tool discovery turns an integration into effective agent authority. An allowlist makes that authority reviewable before it reaches developer machines.

Buildn / client use

Maintain a small approved-server inventory; match remote URLs or exact commands, not friendly server names, and specify an owner and renewal date.

Caveat. This is GitHub-specific enforcement. Names are explicitly not a security control, and policy coverage is limited to supported clients.

Follow-up: Inventory every MCP server in use and classify it approved, experimental, blocked, or unknown.

Enterprises can now install third-party GitHub Apps

platform release2026-08-07test before adoption
  • DIRECT — https://github.blog/changelog/2026-08-07-enterprises-can-now-install-third-party-github-apps/

What it is

GitHub enterprise owners can install external public GitHub Apps; apps with enterprise organization-installation permissions cannot be installed across enterprise boundaries.

Why it matters

Enterprise-level distribution is useful, but the permission model must be designed for the blast radius rather than for the easiest onboarding flow.

Buildn / client use

For any client app, request the smallest permission set, document the installation scope, and avoid cross-enterprise plans if restricted permissions are required.

Caveat. Installing at enterprise scope does not grant organization or repository access by itself; every follow-on permission still needs explicit review.

Follow-up: Create a permission table for the next GitHub App: user, org, repository, enterprise, data read, data write, and exit plan.

Audit Log Drains now support Datadog, Splunk, and Panther

observability release2026-08-07test before adoption
  • DIRECT — https://vercel.com/changelog/audit-log-drains-now-support-datadog-splunk-and-panther

What it is

Vercel Audit Log Drains now stream team activity events plus audit metadata to Datadog, Splunk, or Panther, alongside HTTPS and S3 destinations.

Why it matters

A permission boundary cannot be reviewed after an incident if deployment, access, and configuration actions remain trapped in a vendor console.

Buildn / client use

For Enterprise clients, send audit logs to the existing detection platform and verify retention, alert ownership, and the migration from Custom SIEM Log Streaming.

Caveat. The feature is Enterprise-only; log forwarding is not monitoring until high-signal rules, retention, and response ownership are configured.

Follow-up: Choose three auditable events—access change, production deploy, secret change—and prove they arrive in the team’s response system.
