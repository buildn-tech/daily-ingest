Daily Ingest Dossier — Agent Commerce: Make Payment a Tool Contract

Stripe’s Machine Payments Protocol extends the agentic-web payment lane with an operational implementation: a service can return a payment request, an agent can authorize it, and the resource can be delivered through familiar Stripe settlement and reporting. The near-term opportunity is narrow, metered services—not autonomous purchasing everywhere.
Signal map · request → authorize → deliver

Machine Payments Protocol

new standardprimary source
  • Source: stripe.com

What: Stripe and Tempo launched MPP as an open, internet-native standard for agents to pay services, supporting microtransactions, recurring payments, and fiat or stablecoin flows through Stripe infrastructure.

Why it matters: Payment is becoming another machine-readable capability, which makes small paid APIs and tools easier to expose to agents.

Buildn/client use: Package narrowly scoped Buildn/client services as metered tools: evidence lookup, browser session, rendering, or delivery validation.

Caveat: Payment authorization is a high-impact side effect; do not let an agent choose open-ended spend or merchants.

Next: Prototype a fixed-price sandbox endpoint with a hard budget, allowlist, and human approval.

Payment request as the interface

design patternprimary source
  • Source: stripe.com

What: An agent requests a resource from an API, MCP server, or HTTP endpoint; the service responds with payment terms; the agent authorizes; the resource is delivered.

Why it matters: The protocol makes price and fulfillment part of the tool interaction rather than a separate checkout detour.

Buildn/client use: Represent price, currency, purpose, max amount, refund behavior, and expiry in the tool receipt.

Caveat: Protocol adoption, wallet support, fraud controls, and tax treatment still need validation for each market.

Next: Write a payment receipt schema before integrating any live payment rail.

Agent-native service examples

use casesprimary source
  • Source: stripe.com

What: Stripe cites browser sessions, physical mail, food ordering, climate contributions, and pay-per-API-call examples already using machine payments.

Why it matters: The best first products are discrete services with clear fulfillment and bounded downside.

Buildn/client use: Look for client utilities where a buyer can understand the unit: one render, one lookup, one browser session, one export.

Caveat: Examples are vendor-reported and do not establish demand or unit economics for Buildn.

Next: Select one service and calculate margin after model, infrastructure, payment, and support costs.
