Expanded search for workflow runs in Vercel Observability

What changed
Vercel Workflows now supports structured run filters for workflow, environment, deployment ID, region, and custom attributes, with shareable URL queries.
Why it matters
An incident can now be narrowed to a reproducible slice instead of a vague time window.
Buildn / client use
Buildn: place a stable run attribute on every client workflow. Client work: add a saved incident query to each runbook.
Caveat
Search does not create correlation data; schema and attributes must be designed at dispatch time.
Follow-up
Add client, environment, workflow, and release identifiers to one production workflow.

Custom reporting on AI Gateway

What changed
AI Gateway beta reporting groups cost and usage by model, provider, user, and request tags, including BYOK traffic.
Why it matters
It can make agent margins and client allocations inspectable without maintaining a separate provider-console spreadsheet.
Buildn / client use
Buildn: tag every request with client, workflow, environment, and service tier. Client work: export a weekly feature-cost view.
Caveat
It is beta, Pro/Enterprise-only, and uses paid cardinality and query pricing; do not put unbounded IDs into tags.
Follow-up
Define a four-field tag taxonomy and test one reporting query.

Vercel Observability documentation

What changed
The docs map request, function, external API, and AI Gateway signals across team and project scopes.
Why it matters
It supplies the broader causal trail around a workflow run: route, function, external dependency, then model request.
Buildn / client use
Buildn: link workflow run IDs from delivery artifacts. Client work: use project-level views for service debugging and team-level views for portfolio patterns.
Caveat
Retention and granularity vary by plan and selected projects.
Follow-up
Document the minimum trace path from user request to model cost.
