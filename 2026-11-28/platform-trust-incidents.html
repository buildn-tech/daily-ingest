Saturday, 28 November 2026. The weekend's biggest trust stories share one shape: the layer you trusted most was the one that failed. 1Password's vaults were fine — its developer identity wasn't. Checkout pages were skimmed through a protocol nobody monitors. A ransom-recovery firm was indicted for charging victims for decryption work that was actually a marked-up ransom payment. 1Password: the breach was the CI, not the vault

MaterialSecurityDisclosure
  • source: 1password.com/blog/update-on-nov-2026-security-incident
  • detected: 2026-11-19 · disclosed: 2026-11-25
  • vector: employee GitHub account → malicious push to backend services
  • exposed: names, emails, SRP params, invite/recovery link tokens
  • untouched: vault contents, vault keys, account passwords, secret keys

What happened. An attacker compromised one employee's GitHub account, used it to push malicious code to backend services, and downloaded account metadata for a subset of customers. 1Password rotated exposed credentials, lengthened recovery codes from six digits to ten alphanumeric characters, and states no vault, key, or password was ever reachable.

Why it matters. The zero-knowledge architecture held exactly as designed — and it did not matter commercially, because the headline is still "1Password breached". Source control and CI/CD were the real crown jewels. The same is true for any Buildn client deployment: the deploy pipeline holds more live power than the product it ships.

  • Rotate CI/CD secrets on any GitHub signal
  • Link tokens: make brute-force expensive
  • Disclosure quality is a trust asset
Open question left by the disclosure: no public statement on verifying released client binaries against the source that was copied.

WebRTC skimmers on Black Friday checkout pages

Act nowSecurityE-commerce
  • source: infohawk.com/news/2026-11-27-black-friday-webrtc-skimmer
  • targets: mobile browsers, checkout pages only
  • exfil channel: WebRTC (not surfaced by Chrome DevTools)
  • mitigation: CSP connect-src allowlist + script monitoring

What happened. InfoHawk found skimming scripts live on popular shopping sites timed for Black Friday. The scripts activated only on payment pages and only on mobile, and shipped stolen card data over WebRTC data channels — a path standard HTTP monitoring never inspects.

Why it matters. The mechanism is banal: any third-party JS on a payment page can exfiltrate, WebRTC is just the least-watched pipe. The fixes are old and known — strict CSP connect-src, hosted payment fields, PCI DSS 11.6.1 script monitoring. Any client running an in-page card form needs this checked this week.

  • Set connect-src allowlist on payment pages
  • Hosted fields beat in-page forms
  • Monitor scripts, not just requests
CSP only blocks WebRTC's HTTP-signaling step; a fully credential-less setup can still connect. Assume defense-in-depth, not prevention.

RansomwareHelp: paying the ransom, billing for crypto magic

WatchFraudIncident response
  • source: krebsonsecurity.com/2026/11/cto-of-ransomwarehelp-indicted-for-wire-fraud/
  • claim sold: proprietary decryption, no ransom paid
  • reality (per indictment): paid ransom, billed fictional forensic work
  • sting: FBI posed as both victim and ransomware group
  • markup: ~$6k ransom billed to victim at $16,010

What happened. The company marketed recovery "using advanced cryptographic tools" and even issued signed certificates asserting it never negotiated with attackers. The indictment says it deleted ransom notes via AnyDesk access, paid groups directly, and invoiced victims for "forensic servers" and "decryption processing cycles" that never existed. One real client was quoted $438,880.

Why it matters. During an incident, victims buy certainty under time pressure — the same conditions under which every security vendor recommendation gets accepted. The verification step is technical, not contractual: can the vendor explain the actual recovery mechanism to your engineer?

  • Vet IR vendors on mechanism, not brand
  • Pre-qualify responders before incidents
  • Marketing certificates prove nothing
