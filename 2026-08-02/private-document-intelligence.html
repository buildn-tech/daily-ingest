Keep document intelligence separable: normalize files into durable text, then let a local archive own search, permissions, metadata, and optional suggestions. This week’s releases make that boundary more dependable—not more magical.

Signal map

A deliberately under-covered self-hosted knowledge lane: a fresh Paperless maintenance release fixes AI-suggestion cache isolation and document-processing behavior, while MarkItDown improves structured conversion at the ingestion edge.

Selected dossiers

release

Paperless-ngx v3.0.5

UPDATED 2026-08-01 · DIRECT SOURCE

What: A 21-change maintenance release fixes AI-suggestion caching by model and endpoint, improves empty-field handling, consolidates born-digital PDF detection, and uses server-side iteration for LLM-index updates.

Why now: Model/endpoint-keyed suggestion caching matters whenever a client archive has multiple providers, a staging endpoint, or a local model beside a hosted one.

Buildn/client use: Run a client-safe, self-hosted archive for contracts, invoices, briefs, and project evidence; keep retrieval and document metadata under the workspace’s control.

Caveat: Upgrade notes are maintenance-focused, not a security guarantee. Back up the database and test OCR, custom fields, and any LLM connector against a copied corpus.

Next move: Upgrade a staging instance, then test the same document through two configured suggestion endpoints and verify no cached metadata crosses the boundary.

release

MarkItDown v0.1.7

UPDATED 2026-07-29 · DIRECT SOURCE

What: The converter fixes an O(n²) PPTX-chart lookup, SVG images without a raster fallback in PowerPoint, Office Math template issues, and several LaTeX macro conversions.

Why now: Presentation and equation fidelity determine whether an extraction pipeline is usable as source material for review, search, or agents.

Buildn/client use: Put a local conversion step in front of Buildn/client knowledge ingestion; retain the original file plus generated Markdown as separate artifacts.

Caveat: Conversion is an extraction layer, not semantic verification; inspect representative charts, equations, and images before relying on generated prose.

Next move: Batch-convert five slide decks with charts/SVGs and compare rendered originals against the Markdown before adopting it in an intake workflow.

Paperless-ngx AI suggestion documentation

UPDATED unknown · DIRECT SOURCE

What: The project documents AI-assisted metadata suggestions alongside its existing OCR, correspondence, tags, and custom-field workflow.

Why now: It supplies the operating context for the cache-isolation fix: suggestions should enrich an archive’s metadata, not become the archive of record.

Buildn/client use: Define client-specific document types and custom fields first; add suggestions only after a human can review and correct every proposed label.

Caveat: Documentation configuration is version-sensitive; confirm the installed release’s exact environment variables and provider support.

Next move: Write a two-document acceptance test: correct correspondence, type, tag, and custom-field suggestions with an explicit human approval step.
