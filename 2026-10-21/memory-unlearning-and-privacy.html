Daily Ingest Dossier — Memory Unlearning and Privacy

Memory systems are good at retaining information and poor at removing it precisely. Bemula gives that gap a measurable shape: forget exactly what was requested, preserve unrelated facts, and resist inference from leftovers.

Signal map

Editorial angle: A memory feature is incomplete until it can prove selective forgetting.

Bemula: memory unlearning benchmark

high signalpaper + benchmark
  • source: arxiv.org
  • signal: <1.5% end-to-end pass rate

What it is

Bemula evaluates whether agents can delete requested personal information while preserving unrelated memory, learning replacements, and resisting extraction.

Why it matters

Current memory systems often optimize write and retrieval, not deletion correctness.

Buildn / client use

A direct test plan for Buildn memory and any client knowledge assistant handling sensitive facts.
  • It exposes a product gap with privacy, utility, and evaluation implications.
  • Results use synthetic profiles and may not represent every storage architecture.
  • Next: Implement one paired forget/control test before adding more memory features.

Memory Echo + MEchoBench

adjacentresearch
  • source: arxiv.org
  • signal: echo / contamination

What it is

Memory Echo studies how repeated retrieval and write-back can make one claim look like independent evidence, with metrics for echo density and contamination.

Why it matters

A memory can be confidently wrong because the system amplified its own prior output.

Buildn / client use

Store source-family IDs and correction state; distinguish evidence count from repetition count.
  • Pairs naturally with unlearning: delete echoes, not just the first record.
  • Do not infer production impact from benchmark names alone.
  • Next: Add “independent source count” to memory inspection.

Memorizing Who, Knowing How

schemaresearch
  • source: arxiv.org
  • signal: personal vs procedural

What it is

The work separates personal memory from procedural memory for persistent assistants.

Why it matters

Deleting a personal fact should not erase a reusable workflow, and a workflow should not silently become a user fact.

Buildn / client use

Split Buildn memory namespaces and permissions along this boundary.
  • A simple schema distinction with large privacy and reliability payoff.
  • The separation may be fuzzy for preference-conditioned procedures.
  • Next: Audit five existing memories and classify them.

Reversible context curation

controlresearch
  • source: arxiv.org
  • signal: forgetting as execution

What it is

An agent can remove and restore context during execution, treating context as a reversible resource.

Why it matters

Not every context reduction should be permanent deletion; users need clear distinction between hide, forget, and archive.

Buildn / client use

Design three explicit operations in agent UI and logs.
  • Useful for privacy, focus, and token-budget control.
  • Reversibility can conflict with legal deletion or true erasure requirements.
  • Next: Define retention semantics before implementing a “forget” button.
