Operational Knowledge Systems

Learning and reusable procedure design have been under-covered since mid-July. New role-specific plugins, distributable skill packs, and comment-triggered repository automations show a useful shift from prompt collections to installed, constrained workflows. The useful move is to turn these releases into a small, reviewable operating experiment—not a platform-wide rollout.

Signal map

Editorial read: choose explicit boundaries, preserve evidence, and keep a human acceptance step at the edge of consequential change.

Skill packs are now available on skills.sh

release2026-08-04
What
skills.sh now supports skill packs, installed with npx skills add and updated with npx skills update.
Why now
The unit of reuse shifts from a copied prompt to a named, updatable collection of procedures.
Buildn / client use
Version a Buildn starter pack: research evidence rules, HTML reporting, deployment checks and client handoff.
Caveat
Review source provenance and changes before updating a pack into an active workflow.

FOLLOW-UP → Create a small internal pack with one owner and release notes.

Trigger Copilot automations with comments

release2026-08-03
What
Copilot cloud agent automations can be triggered by configured issue or pull-request comment text.
Why now
A visible comment creates a social and technical checkpoint: intention, scope and resulting artifact are co-located.
Buildn / client use
Use /investigate for stack traces or /docs for docs draft; require the automation to open a reviewable PR or issue.
Caveat
Requires eligible Copilot plans; organizations must enable cloud-agent policy.

FOLLOW-UP → Pilot one non-destructive comment trigger with a required reviewer.
