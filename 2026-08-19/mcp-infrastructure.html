19 August 2026 · selected for portability, observability, and lower operational drag

Executive readout. Tool protocols are becoming ordinary web infrastructure. The important design shift is to make transport stateless where possible, keep application state explicit, and place routing, authorization, telemetry, and cost policy at a control plane rather than inside every agent.

MCP 2026-07-28: stateless by default

spec updateHTTPauth
  • Source: Cloudflare technical overview
  • SDKs: TypeScript, Python, Go, C#

Cloudflare’s overview of the latest MCP specification highlights removal of required protocol sessions, sticky routing, and open streams. Requests carry their own context; application state remains optional and explicit.

  • Deploy request-scoped servers
  • Scale without session affinity
  • Route by method and tool
  • Use Durable Objects only for real state

Buildn/client use: migrate stateless read tools first, then reserve durable state for approvals, jobs, and human interaction.

Caveat: verify exact SDK/spec compatibility and authorization behavior before migration; protocol changes can expose hidden client assumptions.

Action: inventory each MCP tool as read-only, idempotent write, or stateful workflow.

The unified path promises common model entrypoints plus logging, token usage, latency, error rates, cost attribution, provider credits, and future task-based routing.

  • Instrument before optimizing
  • Route by task, not brand

Use now: define a provider-neutral request envelope for every agent call and make missing telemetry a failed test in delivery pipelines.

Caveat: full intelligent routing is described as future direction; treat current behavior as provider abstraction plus observability.

Action: create a small routing table: task class, quality floor, latency ceiling, spend ceiling, fallback.

System Initiative: control before autonomy

reported product signalapproval

System Initiative’s infrastructure agents use a digital twin, produce a plan, require engineer review, then execute under policy checks and tests. It is a concrete pattern for making “agent autonomy” a bounded workflow rather than a binary switch.

  • Preview changes as artifacts
  • Make policy testable
  • Keep human approval explicit

Use now: apply the same boundary to client handoffs and publishing: plan, diff, approval, publish, verify.

Action: add an approval state to one Buildn workflow and log who approved which plan.
