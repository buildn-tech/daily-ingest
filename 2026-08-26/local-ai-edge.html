What it is

NVIDIA positions Nemotron 3.5 Lightning as a fast, specialized model for agentic tasks and part of a broader local ecosystem.

Why it matters

Buildn / client use

Use it as a low-risk router target for artifact classification, metadata cleanup, or local coding assistance.

Portable Computer: local-first personal agent

WATCHproduct
  • Signal: Perplexity / NVIDIA announcement · Aug 25
  • Open: https://pplx-dgx-spark-lp-demo.pplx.app/

What it is

A local-first agent concept for DGX Spark that can connect to Drive, Gmail, Slack, and GitHub while switching between local and cloud models.

Why it matters

The hybrid boundary is the interesting part: sensitive routine work can stay local while difficult work escalates.

Buildn / client use

Prototype a Buildn private-context assistant with explicit per-tool residency labels.

Why useful now

It offers a concrete product shape for local/cloud fallback instead of an all-or-nothing migration.
Caveat: Availability, supported hardware, and integration depth may change quickly.

Follow-up

  • Map Buildn data classes to local-only, hybrid, and cloud-eligible routes.
  • Make residency a visible policy, not a hidden model choice.

NeMo Switchyard routing

ADAPTarchitecture
  • Signal: NVIDIA local AI roundup · Aug 2026
  • Open: https://developer.nvidia.com/nemo

What it is

A routing pattern that sends workflow steps to models based on speed, accuracy, and cost.

Why it matters

Routing at step level is more actionable than selecting one “best” model for an entire agent.

Buildn / client use

Add route decisions to Buildn artifact jobs: extract locally, synthesize remotely only when needed.

Why useful now

It makes model portfolio governance tangible and measurable.
Caveat: Treat the product page as a starting point; integration details need verification.

Follow-up

  • Define three route classes and log the reason for every escalation.
  • Turn model choice into an auditable workflow decision.
