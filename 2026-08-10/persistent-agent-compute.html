Persistent Agent Compute

Executive readout: AWS has moved long-running agent execution from a bespoke infrastructure problem into a managed runtime choice. The practical design question is no longer “can this agent run?” but “which work deserves persistent capacity, and how do we stop idle compute becoming invisible spend?”

Fresh · GAInfrastructure

Signal map: short-lived control, persistent workers

Pattern: Keep routing and aggregation cheap; reserve persistent compute for work that benefits from shared state, OS access, GPU, or multi-day continuity.

  • Separate control plane from workers
  • Persist state intentionally
  • Hibernate idle sessions
General availabilityAWS

AgentCore runtime instances

  • Published: 2026-08-06
  • Regions: 9 listed by AWS
  • Sessions: up to 14 days

What it is: AWS-managed EC2-backed capacity inside Bedrock AgentCore, with instance selection, provisioning, patching, scaling, and lifecycle management handled by AgentCore.

Why it matters: Persistent agents can use GPU, memory-optimized hardware, direct OS access, shared files, and multiple agents on one host without each team rebuilding fleet operations.

Buildn/client use: Prototype a durable research or document-processing worker, while keeping the coordinator on a short-lived runtime. Treat capacity providers as an explicit policy boundary.

Caveat: You still pay management and EC2 charges; 14-day continuity does not remove state, access, or shutdown design.

Follow-up: Cost a 48-hour pilot with hibernate/resume and a hard idle budget.

Practical patternMulti-agent

Shared-file collaboration beats message plumbing

What changed: AWS’s example uses a code writer and reviewer that collaborate through a shared session directory rather than calling each other’s APIs.

Why it matters: A filesystem can be the simplest handoff surface for large artifacts, intermediate code, and review evidence. It also makes the boundary inspectable.

Buildn/client use: Use a manifest plus immutable artifact directory for delegated work: writer output, reviewer notes, test evidence, final approval.

  • Fewer coordination APIs
  • Large artifacts stay out of prompts
  • Evidence remains addressable

Caveat: Shared state needs tenancy, cleanup, and concurrency rules.
