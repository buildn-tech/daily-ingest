KnowBody suggests a useful architecture beyond robotics: keep the foundation model stable, and put task-relevant, revisable knowledge in an explicit harness. The important object is not “memory” in the abstract; it is a model of what actions are possible, how evidence changes it, and which dependent beliefs must be rechecked.

KnowBody: embodiment outside the weights

fresh researchrobotics
  • Submitted: 22 Sep 2026
  • 32 fixed-budget trials · 4 real-robot tasks
  • Paper → · Project page →

What it is: a partial action-relevant body model initialized from one off-task trajectory; new observations refine it, and dependent knowledge is rechecked when assumptions change.

Why it matters: the harness provides adaptation without updating VLM weights. Reported completion was 75% versus 25% for the native harness, with 29–53% fewer planner rounds by the fifth success.

Buildn/client use: represent agent capabilities, permissions, and environment assumptions as inspectable state rather than hidden prompt context.

  • Freeze core model behavior
  • Externalize action constraints
  • Revalidate dependent facts
  • Persist only useful state
Caveat: the evaluation is small and task-specific; treat the architecture as the signal, not the headline percentage.

Harness pattern: queryable, revisable, provenance-bearing

transfer patternhigh leverage

A durable agent harness should answer four questions before execution: what does this worker believe, what can it do, what evidence changed the belief, and what outputs depend on it?

  • State has owners
  • Updates have evidence
  • Beliefs have expiry
  • Revisions trigger rechecks

Buildn/client use: apply this to client conventions, tool manifests, environment facts, and approval rules—not only to physical-world models.
