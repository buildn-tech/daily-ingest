MeMoREval tests embodied memory modalities

fresh signalembodied

What it is. The Oct 8 benchmark compares text, descriptions, frames, and scene graphs for embodied agents; frames plus scene graphs reached the strongest aggregate success in the reported study.

Why it matters. For Buildn, the analogue is evidence plus structure: preserve source artifacts while maintaining queryable summaries and relations.

  • Buildn/client: Run a memory ablation: transcript only, summaries only, raw evidence plus index.
  • Useful now: direct, testable change
  • Caveat: validate claims on your own task mix

MemoryAgentBench covers four competencies

fresh signalbenchmark

What it is. The ICLR benchmark evaluates accurate retrieval, test-time learning, long-range understanding, and selective forgetting through incremental multi-turn interactions.

Why it matters. A memory feature that only recalls facts can still fail at learning, updating, or forgetting. Add all four dimensions to product acceptance.

  • Buildn/client: Write four tiny evals against the current Buildn memory layer.
  • Useful now: direct, testable change
  • Caveat: validate claims on your own task mix

Memory modality is a product choice

fresh signaldesign

What it is. MeMoREval reports that modality performance depends on model, task, backend, and accumulated experience; selective retention saves storage but can reduce success.

Why it matters. Storage optimization should be downstream of task loss, not the first design goal. Retain costly evidence when recovery is impossible.

  • Buildn/client: Classify records by recoverability before pruning.
  • Useful now: direct, testable change
  • Caveat: validate claims on your own task mix
Open source ↗

Coding agents need realistic session memory

fresh signalcoding

What it is. JetBrains Research analyzes 4,782 sessions and argues benchmarks must match user task flows, including multi-turn switching among questions, planning, execution, and review.

Why it matters. Agent memory and agent evaluation are coupled: a one-shot benchmark hides the context transitions real users create.

  • Buildn/client: Log task transitions, not just final success, in coding-agent trials.
  • Useful now: direct, testable change
  • Caveat: validate claims on your own task mix
Open source ↗

Memory quality needs cost curves

fresh signaleconomics

What it is. MemoryAgentBench and MeMoREval both make retrieval/write tradeoffs visible; success alone cannot select a production architecture.

Why it matters. Treat memory as a budgeted subsystem with write cost, read cost, latency, evidence coverage, and error recovery.

  • Buildn/client: Add cost-per-success to the next retrieval experiment.
  • Useful now: direct, testable change
  • Caveat: validate claims on your own task mix
