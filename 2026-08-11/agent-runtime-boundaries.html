Cloudflare Computer

early previewopen source
  • source: Cloudflare Blog · 2026-08-03
  • repo: github.com/cloudflare/computer

What: A computer-like agent environment spanning isolates, containers, and eventually browsers over one synchronized filesystem.

Why: It avoids paying container cost for every idle or lightweight agent action.

Use: Buildn workers can keep orchestration durable while escalating package installs, native binaries, or tests.

  • Cheap idle state
  • Heavy work on demand
  • Audited operations
Caveat: early preview; validate isolation, filesystem semantics, and failure recovery.

Action: Recreate the pattern with a small task router and two execution classes.

Vercel Managed Images

availablereproducibility

What: Versioned open-source base images replace Sandbox runtimes, with a universal Ubuntu image preloaded for coding agents.

Why: Nightly rolling tags improve patch velocity; digest pins preserve immutable builds.

Use: Standardize Buildn report-rendering and test sandboxes; pin digests for client delivery.

  • Known starting point
  • Nightly security updates
  • Digest-level rollback

Action: Create a two-tier image policy: rolling for experiments, digest-pinned for releases.

Cloudflare Agents Week

operating model

What: Cloudflare groups runtime, traces, previews, approvals, workflows, and issue triage under an Agent Development Lifecycle.

Why: The hard part is no longer generating code; it is validating, deploying, operating, and repairing it.

Use: Turn dossier production into a workflow with replayable evidence and a publication gate.

  • Lifecycle beyond prompts
  • Local traces matter
  • Approval is a primitive

Action: Map one Buildn workflow from intake through published artifact and identify its replay boundary.
