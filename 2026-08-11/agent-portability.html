Agent Plugins 1.0.0

specificationportable packaging
  • source: Google Developers Blog · 2026-08-06
  • shape: plugin.json + skills/ + mcp.json

What: An open, vendor-neutral directory format for shipping related skills and MCP servers together.

Why: It removes client-specific layout drift without pretending to solve installation or trust.

Use: Package Buildn research, report, and archive skills once; expose client-specific extensions under a namespace.

  • One wrapper, many clients
  • Explicit transport types
  • Independent component failure
Caveat: v1 does not define permissions, sandboxing, provenance, or approval.

Action: Draft a Buildn plugin manifest and document its permission review separately.

skills.sh packs

try nowdistribution

What: Bundle community, local, ZIP, or GitHub skills into an unlisted shareable pack.

Why: A single install/update command makes team-standard agent behavior reproducible enough for pilots.

Use: Create a “daily ingest authoring” pack for report structure, source verification, and HTML QA.

  • Fast team rollout
  • Updateable bundle URL
  • Low coordination cost
Caveat: a pack is distribution, not a signed supply-chain boundary.

Action: Prototype one private pack; record version, sources, and review owner.

ADK for Java 1.0.0

runtime patternselective

What: Production-oriented agent kit with plugins, context compaction, HITL, sessions, artifacts, and A2A.

Why: It demonstrates that portability needs application-wide interception, not only portable prompts.

Use: Borrow the “global plugin” pattern for logging, guardrails, and context filtering in Buildn workers.

  • Controls across hierarchy
  • Artifact-aware sessions
  • Human approval pause

Action: Define three global hooks: before-tool, after-tool, and artifact publication.

Portable does not mean safe

design rule

Packaging solves “how does this travel?” It does not solve “what may it do here?” Keep identity, permissions, provenance, and approvals outside the portable core.

  • Separate package from policy
  • Make trust explicit
  • Fail closed on tools
