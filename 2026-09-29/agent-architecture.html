Agent count is a task-shape decision

revisit: appliedarchitecture
  • Source: Google Research: Science of Scaling Agent Systems
  • Signal: Material synthesis: architecture beats “more agents”

What it is

A study of 180 configurations finds centralized systems help parallelizable work, while independent agents can amplify errors on sequential tasks.

Why it matters

It gives a falsifiable reason to avoid multi-agent theater: choose topology from decomposability and tool complexity.

Buildn / client use

Add task-shape classification before spawning workers in Buildn or client automations.
  • Parallelize independent evidence
  • Keep sequential loops coherent
  • Measure error amplification
Caveat / next move: The source is not new today; it earns a revisit because it is the decision rule behind today’s runtime experiments.

Dynamic workflows as reusable infrastructure

  • Source: Claude Code dynamic workflow field notes

What it is

Saved workflows can fan out, critique, filter, and verify work rather than relying on one long prompt.

Why it matters

The useful unit is a bounded workflow artifact with an entry condition, budget, and verifier.

Buildn / client use

Create three Buildn templates: research fan-out, implementation loop, and release verification.
  • Workflows become shareable
  • Budgets become explicit
  • Verifiers close loops
Caveat / next move: Avoid copying vendor-specific commands; preserve the control pattern, not the syntax.

Agent privacy evaluation as a test harness

OSS benchmarkevaluation
  • Source: AgentDojo benchmark
  • Signal: Concrete adversarial tasks for tool-using agents

What it is

AgentDojo supplies environments and attacks for evaluating prompt injection and tool-use safety.

Why it matters

A repeatable attack suite is more useful than a one-time red-team demo when workflows and models change.

Buildn / client use

Adapt two synthetic tasks into a regression suite for tool permissions and prompt-injection resilience.
  • Replayable attacks
  • Tool-aware evaluation
  • Useful CI gate
Caveat / next move: Benchmark assumptions may not match your tools; fork only the smallest task set and document adaptations.

MCP v2 direction: stateless, deployable tool surfaces

protocol watchinfrastructure
  • Source: Cloudflare: The next generation of MCP

What it is

Cloudflare describes a stateless MCP core designed for Workers, with protocol upgrades and an SDK migration path.

Why it matters

Statelessness and deployability reduce the friction of making tools portable across agent runtimes.

Buildn / client use

Review Buildn MCP tools for explicit auth, idempotency, and request-scoped state before adding more connectors.
  • Less hidden session state
  • Portable deployment target
  • Clearer migration boundary
Caveat / next move: Protocol previews can shift; pin versions and test interoperability with two clients.

Chopin: planning before delegated execution

prototypecollaboration
  • Source: GitHub Next Chopin
  • Signal: Planning surface remains under-covered

What it is

Chopin combines human presence, shared plans, chat, and MCP in a multiplayer agentic planning environment.

Why it matters

It reinforces a useful separation: decide and record the plan before workers mutate repositories or external systems.

Buildn / client use

Prototype a static Buildn plan card that captures intent, constraints, owners, and approval before execution.
  • Plans become artifacts
  • Presence supports steering
  • Decisions stay reviewable
Caveat / next move: Prototype, not production software; borrow the interaction model only.
