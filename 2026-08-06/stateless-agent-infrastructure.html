Stateless Agent Infrastructure

Two agent architectures must coexist: tool calls want stateless transport and ordinary HTTP operations; real-time conversations still hold durable runtime state. Keep those boundaries explicit, then give operators a local surface for parallel work.

Signal map

Do not “statelessify” application conversation state. The MCP change removes transport affinity, not the need to model durable workflow state.

Primary · Aug 5

MCP transport goes stateless

The 2026-07-28 MCP release candidate removes the handshake and Mcp-Session-Id; request metadata is self-describing.

Why it matters: ordinary load balancing, scale-to-zero and failover no longer need sticky routing or a session cache.

Follow-up: inventory remote MCP servers that still require affinity or Redis solely for protocol sessions.

Primary · Aug 3

Session-aware real-time capacity

For long-lived voice/video agents, QPS and CPU miss committed concurrency. The runtime should report active sessions, with correct cleanup on cancellation and disconnect.

Buildn/client use: route live browser or voice agents by sessions plus utilization, not connections alone.

Caveat: session count complements CPU/memory; it is not a static capacity proxy.
