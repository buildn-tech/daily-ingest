Daily Ingest Dossier — Agent Routing Economics

2026-07-31 · adaptive lane

Routing can now be a workflow decision: reserve Sol for uncertainty, move defined background work to Luna, and pay the Fast premium only when latency has a measurable business value. Re-baseline rather than assume the old mix remains rational.

← today’s overview

Signal map

A same-day OpenAI price and latency update materially changes the economics of high-volume agent work; this is a concrete update to the model-choice lane covered July 29, not a repeat of its earlier policy framing.

actionable signal01

Re-price the background queue

What: Luna is now $0.20 input and $1.20 output per million tokens, according to OpenAI.

Why it matters: High-volume, tool-using and multi-step work has a new cost baseline.

Buildn / client use: Move deterministic extraction, test-writing, evaluation, and batch enrichment to a controlled Luna cohort.

Caveat: Price is not quality evidence; compare completion, rework, and escalation rates.

Follow-up: Run 50 historical tasks through the current route and Luna; record outcome cost.

actionable signal02

Keep uncertainty on the high tier

What: OpenAI positions Sol for consequential work and Luna for well-defined execution.

Why it matters: The price cut is useful only when routing follows task uncertainty rather than model fashion.

Buildn / client use: Use Sol for plan and exception resolution; give workers bounded implementation and verification jobs.

Caveat: Model labels are vendor positioning, not an acceptance test.

Follow-up: Write a three-tier routing rubric with explicit human escalation.

actionable signal03

Treat Fast mode as a service level

What: Sol Fast replaces Priority Processing and is stated to offer up to 2.5× speed at 2× the price.

Why it matters: Latency becomes an auditable per-workflow trade-off, not a blanket account setting.

Buildn / client use: Use it for live operator or client interaction; preserve Standard for queued work.

Caveat: Actual latency and quality vary by prompt, tool calls, and capacity.

Follow-up: Measure p50/p95 latency, completed-work rate, and dollars per finished task.
